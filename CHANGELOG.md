# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Dashboard: a Flow tab, now the first one. For this project it lists each call and done-gate stop of the last 1, 7 or 30 days as what was asked, what went to Jev (requests, cached answers, tokens, time) and the verdict, with Jev's stored answer to each question on demand. It reads the receipts, the answer cache and `stops.jsonl`; nothing new is stored or sent.
- `done`: a `bun test` parser. It reads the summary (` N pass`, ` N fail`, ` N skip`, ` N todo`, ` N error`, `Ran N tests across N files.`) and `(fail)`, `(skip)` and `(todo)` lines, and claims only a log that shows a failure: ` N fail` or ` N error` above 0 next to the `Ran` line, or a `(fail) name` line (with no summary, at least one failure and the run marked incomplete). A failing bun run piped through `| tail` with `exit code: 0` is now a conflict (`unsure`); before, nothing read it and the tail's exit code gave `met`. A clean bun log keeps its exit-code reading, so the recorded facts of `done-v2-h4` case `h4-c-02` (a clean bun run with skips) do not change; a failing one with no exit line now reaches Jev as facts (`failed: N`), like every other parsed runner, instead of being unparsed.

### Changed

- CI and `npm run ci:local` also run the tests on Node 26.
- The bundles are built with whitespace-only minification (names kept): `dist/cli.mjs` goes from 392,827 to 318,049 bytes and `dist/hook.mjs` from 184,329 to 142,960, under the unchanged 400,000 and 200,000 byte tripwires. Start latency showed no difference beyond noise. Chosen with `decide` after measuring (p 1.0, both orders); [record](docs/decisions/bundle-minify.md).

### Fixed

- `node:test`: `ℹ cancelled N` (or `# cancelled N`) above 0 counts as N failures and marks the run incomplete, so a timed-out or cancelled test in a run whose summary says `fail 0` no longer reads as a pass. The names under `✖ failing tests:` count as failing, with or without a duration; the list ends at the next unindented line that is not blank, `test at`, `✖` or `⚠`, so a later run's failures still count. A failing todo test (`⚠` in that list, `not ok N - ... # TODO` in TAP) is a todo, not a failure. `ℹ todo N` counts as skipped, and the skip markers read `ℹ todo 1` and `ℹ skipped 2` as they already read the `#` form. A test marked `expectFailure` (`... # EXPECTED FAILURE` on a passing line, spec or TAP) is an expected failure and caps `met`.
- `cargo test --no-fail-fast`: the closing `error: N targets failed:` line is a failure (at least N). A tail that cut off the failing target's own `test result: FAILED` line was read as all passed.
- Exit code lines: a line is no longer read as an exit code when it is a source frame (`8 |   test("exits with exit code 0 ...`), a passing, skipped or suite title line (`✔`, `✓`, `↓`, `▶`, `# Subtest:`, `(pass)`, `ok 1 - ...`), an assertion message (`expected exit code 0, got 2`, `exit code = 2, want 0`), or when the phrase sits inside an open quote (a test title). A failure line (`✖`, `×`, `(fail)`, `not ok 1 - ...`) keeps a non-zero code, so `✖ Command failed with exit code 1` is still `missing`; only a 0 on such a line is dropped as a title. A hex code (`exit code 0xC0000005`) is read as its value instead of 0. One rule now serves the evidence parser and the build parsers' exit codes; the `cargo build` check for output after `Finished` keeps its looser match, so a traced `+ echo 'exit code: 0'` is not extra output.
- Pest summary lines (read by the `jest` parser): `risky`, `incomplete` and `todos` (Collision's plural) count as skipped and cap `met`, as the PHPUnit parser already did, and a line with only risky tests (`Tests:    2 risky (0 assertions)`) is read as a summary instead of falling back to the exit code. The runner keeps the `jest` label, because relabelling would change the recorded facts of `done-v2-h6` case `h6-f-07`.
- vitest: `N expected fail` on the `Tests` line is an expected failure and caps `met` like a pytest xfail.
- Skip markers: `risky`, `incomplete`, `todos` and `expected fail` counts are skip markers, so a count in an earlier run of a log with two summaries still caps `met` when the last summary is clean, as `skipped` already did.
- `dotnet test`: a build error needs the MSBuild shape `origin: error CODE:` with a code other than `TS`, so tsc output is read by the `tsc` parser alone and no longer adds a `dotnet test` runner. The `tsc` parser reads error lines behind a monorepo, CI timestamp, BuildKit or Angular prefix (`web:typecheck: `, `2026-10-06T12:00:00Z `, `#12 4.123 `, `Error: `) and Angular `NG` codes, so such an error with `exit code: 0` is a conflict (`unsure`), never `met`.
- These were reproduced with real tool output on local synthetic projects and re-reproduced independently, then reviewed and reproduced again; the fixes are fitted to those reproductions, not measured. No facts sent to Jev changed for any eval case (two tsc cases with a non-zero exit code lose a spurious `dotnet test` runner), and `eval score --suite all` is unchanged. Record: [parser-defects-2026-10-06.md](docs/decisions/parser-defects-2026-10-06.md).
- CI logs: known GitHub Actions line prefixes are stripped once per line before any parser, the exit-line rule and the skip markers: `gh run view --log`'s `job<TAB>step<TAB>2026-10-07T00:26:55.4401234Z ` and a raw job log's `2026-10-07T00:26:55.4401234Z ` (a byte order mark included). A tsc error read through `gh run view --log` with `exit code: 0` gave `met`: the first round's anchoring of the `dotnet` pattern had removed the only reader of such lines. It is a tsc error again, and `##[error]Process completed with exit code N.` is read as an exit line (the timestamp had pushed it past the exit pattern's 60-character window), so a failed CI log is `missing`.
- `node:test` under `| tail`: a window that holds only part of a failure's details, with no summary and no `✖` line (`code: 'ERR_ASSERTION',`, `failureType: '...',`, `diff: 'simple'`, a `TestContext.<anonymous>` or `node:internal/test_runner` stack frame, `'test timed out after Nms'`), counts as one failure and marks the run incomplete, so the tail's `exit code: 0` is a conflict (`unsure`) instead of `met`. `code: 'ERR_ASSERTION',` and `diff: '...'` count only when the log has no jest, vitest, bun or mocha summary: any logged `AssertionError` prints them, and a passing jest, vitest or bun run that logs one would otherwise lose `met` and show the Stop gate a failed check. Details owned by a todo's `⚠ name (Xms)` entry are not a failure; a `⚠` line inside an error message (a lint warning in the thrown text) does not own the frames after it. A log with a summary is read from its summary as before.
- `node:test` todo and skip lines with a reason: `⚠ name (Xms) # <reason>` (a failing todo), `✔ name (Xms) # <reason>` (a passing todo) and `﹣ name (Xms) # <reason>` (a skip) count as skipped with or without a summary, inside or outside the failing list. A tail or a clipped log whose `ℹ todo N` line was cut off is capped instead of `met`; node prints the reason in place of `# TODO`, so neither the parser nor the skip markers saw these lines before. With a summary, its count stands (the lines are not added to it).
- CI logs: `##[error]The operation was canceled.`, `##[error]The job has exceeded the maximum execution time ...` and `##[error]The runner has received a shutdown signal` mark every parsed runner incomplete, so a timed-out job whose log still holds earlier steps' passing summaries is capped (`unsure`, `incomplete_run`) instead of `met`. Stripping the prefixes had made those summaries readable.
- Monorepo wrappers: a non-zero exit report from turbo (`ERROR  run failed: command  exited (1)`, a task's `ERROR  command ... exited (1)`), nx (` NX   Running target(s) ... failed`, read as 1), `bun run` (`error: script "test" exited with code 1`), `bun --filter` (`pkg script: Exited with code 1`), concurrently (`[web] ... exited with code 1`) and npm 10+ (`npm error code 1`, behind a task prefix too) is an exit line when the log's own exit lines show no non-zero code, so a failed workspace run piped through `| tail` with `exit code: 0` is `missing`. A zero code is never read, and a log that already has a non-zero exit line keeps its exit lines unchanged.
- `bun test`: lines behind `bun --filter`'s or `pnpm -r`'s `pkg script: ` prefix are read; `snapshots: ... N failed` is a failure (a `| tail -n 3` window holds it without the ` N fail` line); `error: regex "x" matched 0 tests` is an error in an empty run (bun exits 1), so with `exit code: 0` it is a conflict.
- `node:test` TAP: a describe-level `after()` hook failure, which TAP counts as `# fail 0`, is a failure when its YAML (`failureType: 'hookFailed'`, a `TestHook.run` or `Suite.runHook` frame) is in the log and the summary counts no failure or cancellation. A failing todo's YAML is not one.
- These came from a second review with real gh, Node 26.9 and bun 1.4 output, and a re-review of those fixes with real jest 30, vitest 5, turbo, nx and npm 11 output; fitted, not measured. No facts sent to Jev changed for any eval case, and `eval score --suite all` is unchanged. Record: the follow-up and re-review sections of [parser-defects-2026-10-06.md](docs/decisions/parser-defects-2026-10-06.md).

- `claims`: claim ids must be unique; a repeated id is `bad_input`. Before, two claims with the same id (an explicit id equal to another claim's position, for example) shared one code check and one Jev answer, so a claim quoting text that is not in the source could be counted as supported. A claim with the id `__proto__` keeps its `reasons` and `p` entries in the output; before, they were dropped.
- The GitHub Action passes the added doc lines to `claims` as JSON lines, one `{"text"}` object per line, so no doc line is read as JSON. Before, a first added line starting with `[` (a markdown link) or added lines that all start with `{` (JSON samples in a fence) were read as JSON: the CLI failed with `bad_input` and the claims step only warned and checked nothing, or it checked the samples' `text` fields instead of the doc lines.
- `judge` and `claims` read text that starts with `[` but does not parse as JSON as plain lines, such as a first line `[Configuration](docs/configuration.md) explains it` or `["Quick start"](docs/start.md) ...`. It is still `bad_input` when it looks like a broken JSON array: a first line that is only `[`, or text that starts with `["`, `[{` or `[[` and ends with `]`. A leading UTF-8 byte order mark is ignored; before, it broke JSON lines and stayed in the first plain item.
- `eval record --max-usd` refuses with `bad_input` when the model has no known price; before, the cap was skipped without notice. A receipt of a run answered by a model with no known price records `cost_usd` as `null` instead of 0.
- When a request fails, a run waits for the requests still in flight and starts no new ones before it writes its receipt and reports the error. Before, the receipt missed the tokens and request ids of requests that were still running.
- The answer cache is kept per endpoint: with `TYPESAFE_BASE_URL` pointing somewhere other than the default, answers are cached apart, so one endpoint's answers are not served for another. Cache keys for the default endpoint are unchanged.
- Pack redaction patterns ignore the `g` and `y` flags. Before, a stop pattern with `y` matched only at the very start of a field, and one with `g` kept its position from one field to the next, so either could miss a credential.
- An empty `REFEREE_PACK` or `--pack ""` counts as unset, so the project file's pack applies; before, it fell back to `generic`.
- `thresholds` in `.claude/referee.local.json` merge per question and key over the project file's. Before, a personal `thresholds` object replaced the project's whole set and could drop a stricter team value.
- `decide`: an exact tie at the top of one option order counts as no leader for that order, so `order_disagrees` is true and two orders give `tie`. Before, the leader of a tied order followed the key order of Jev's answer. Rescoring `decide-best` gives the same full-run numbers; with `--ablation context` one case (`vb1-migration-window`, whose reversed order ties at 0.46) moves from `weak` to `tie`, so that run reads 8/23/8 with 7 order disagreements instead of 8/24/7 with 6, agreement unchanged. The next step then says an option order had an exact tie at the top, not that the orders picked different leaders.
- `receipts`, `receipts overrule` and the dashboard skip receipt lines that are valid JSON but not an object with a string `id` and `ts` (`null`, a number, `{"ts":{}}`), which crashed them, and read `overruled.jsonl` line by line, so one torn line no longer clears every overrule.
- `receipts --usage` counts CLI calls behind `env` with flags (`env -u KEY`, `env --unset KEY`), `timeout` (`--signal KILL` included), `nohup` and `xargs` (`--max-args 1` included).

- `ui`: a reply for a tab you already left no longer draws over the current tab, and a label that lands after a tab switch no longer redraws the queue there. Before, a slow Flow reply could replace the labelling queue, and R or W then labelled a stop that was not on screen. Labelling keys now do nothing while the queue loads, and a label removes the stop it was sent for, even if the card moved on in the meantime. R or W pressed while the previous label is still saving was dropped without a word; the status line now says so, and the confirmation names the stop by its time.
- `ui`: Flow reads at most 12 stored answers per call and 600 per response. The collapsed answers line and the note under it say how many it did not read, and when the 600 ran out, which filter leaves more room. Before, it read every cache entry of every call it showed. On a synthetic data directory with one 240-key `judge` receipt and 80 other events, the `/api/flow` response went from 178,674 to 87,887 bytes. The median of five requests went from 30-45 ms to 8-10 ms over three runs each, and part of that gain comes from the project id fix below.
- `ui`: Flow counts a stored answer older than the 30-day cache life as gone instead of showing it. The Privacy tab and `docs/privacy.md` no longer say that cache entries expire. They are not reused after 30 days, but the files stay on disk until `receipts overrule` removes them, you delete `cache/`, or uninstalling removes the data directory.
- `ui`: a request target with a backslash gets 400 before it is parsed. Before, `/\` gave 500 ahead of the token check, and `/\evil/api/flow` was served as `/api/flow`. A path that URL parsing would change, such as dot segments (`..`, `%2e`) or a `{`, gets 400 too; before, `/x/../api/flow` was served as `/api/flow` after the same Host, Origin and token checks, while `docs/decisions/ui-security.md` said it ended in 400 or 404.
- `ui`: a cache entry whose `model` or `choice` is not a string shows `?`. Before, an object with a non-function `toString` failed the Flow route with 500, and a plain object showed `[object Object]`. A numeric `model` now shows `?` too.
- `ui`: the project id and the transcript folders for the queue's hints, each of which runs `git`, are worked out once per server. Before, every API request ran `git` once or twice.
- `ui`: on a 375 px screen, an open table of Jev's answers wraps long question ids and option names inside the cell instead of scrolling the whole page sideways.
- `ui`: `opened` in the listening line is true only when `open` or `xdg-open` actually started. A missing opener gives false, and its launcher file is removed at once. `--describe` documents `opened`, names the Flow tab, and says the URL lets its holder read receipts, stops and Jev's stored answers, and label stops.

- Stop hook: when the Jev call fails or redaction stops the request, it now writes a receipt with the error code, and the stop record keeps the code in `error`. Before, no receipt was written and the code was lost. As in the CLI, the receipt's `requests` counts answered calls only, so a call that reached Jev and failed also shows 0.
- Stop hook: a request stopped by redaction is recorded as `credential`, a missing or malformed key as `no_key`, and a pack that does not load or lacks the `stop.*` questions as `config_error`, each with its code. Before, all of them were `jev_error`, so `errors` and `error_rate` in `receipts --stops` and the dashboard counted local refusals and configuration mistakes as Jev failures (a wrong pack name gave an error rate of 1.0 with no request sent). Only `jev_error` and `breaker_open` count now. A project file that does not load is still not recorded, since the gate mode cannot be read from it; `doctor` reports it as `project_error: bad_project`.
- Stop hook: `hooks.stopGate: "active"` (not built yet) still runs as `shadow`, but the record now carries `configured: "active"` and `doctor` reports `stop_gate` with a note. Before, nothing said that the setting had no effect.
- `doctor` loads the project file and its pack (and the `stop.*` questions when the done-gate is on) and reports `project_error` with the code and a `next_step`; the verdict does not change, since a `packs_dir` plugin setting reaches hooks but not the shell. Before, it only checked that the project file existed.
- Done-gate transcript reading: an Edit or Write that Claude Code refused before applying it (a permission or hook denial, or a tool error such as "String to replace not found") no longer counts as an edit, so it no longer makes a turn without edits ask Jev or cancel a passing check that ran before it. Other tool errors still count. A prompt that is only a pasted image (no text) now starts a new turn, so the stop after it is no longer judged on the previous turn's edits; the label hint of `receipts --stops` still reads past such a prompt, as before. The request for every session of the recorded stop suites is unchanged.
- `stops.jsonl` past 2 MB was read and rewritten on every append, and a rewrite could drop records that other sessions appended at the same time. It is now pruned only when its oldest record is a day past the 90-day retention (so at most about once a day), under a lock taken without waiting (another session pruning means skip), through a temporary file and a rename, copying the lines appended meanwhile. An append that reached the old file just after the rename is written again, and a stop stored twice that way is read, counted and pruned as one.
- The hook circuit breaker kept every session in one `breaker.json` rewritten without a lock, so parallel sessions could overwrite each other's failure counts and open their breakers late. It now keeps one small file per session under `breaker/`, written through a temporary file and a rename; the old `breaker.json` is removed.
- The Clopper-Pearson interval behind `threshold_suggestion` recomputed every binomial coefficient on each bisection step, which took seconds at a few hundred labels (about 20 s for 5,000 of 10,000). It now computes them once per interval with the same arithmetic, so results are bit-identical (tested against the old computation on a grid) and that case takes well under a second.
- Removed the skip reasons `hooks_off` and `project_off` from the stop record type: they were never written (with hooks or the gate off nothing is recorded). Readers still accept any stored reason.

- `--describe` names every top-level key a command prints. `doctor` lacked `version`, `node`, `claude`, `key_error`, `online`, `models`, `model`, `data_dir`, `data_bytes`, `project` and `stop_gate_note`; `done` lacked `exit_code`; `receipts` lacked `days`, `id`, `receipts`, `out`, `project` and `calls`; `eval` lacked 18 keys, among them `suites`, `cases`, `sweep` and the ablation fields. Keys every command shares (`ok`, `receipt`, `requests`, `cached`, `details`, the `--dry-run` fields and the error-line fields) are in a new `outputs_common` block. A test fails when a command prints a key that is not in its contract, and also when its calls no longer print every key of a command's own outputs, so each of those keys is reached at least once (decide's `per_option` mode, an `eval record` top-up, a `--sweep` with no suggestion and a rate-limited error line among them).
- `--verbose` is listed in `--describe` and `--help`; it was accepted by every command but missing from both. `eval record --verbose` now prints the same stderr line as `done`, `decide`, `judge` and `claims`; before, it printed nothing. `--help` also says that every command takes `--pack` and `--fail-on`.
- `done` on evidence with a non-zero exit code writes a receipt (0 requests, verdict `missing`, `reason: exit_code_nonzero`) and prints its id, as the README and the skill say commands that ask Jev do. Before, it wrote none and printed none. `done --dry-run` on such evidence prints that offline verdict with `dry_run: true`, so `--fail-on missing` exits 3; before, it printed `would_send` with 0 requests and exited 0 (0.1.4 said `--dry-run` still showed the request; since the exit-code check moved ahead of the request, there is none to show). A receipt now keeps a `done` result's `reason`.
- `SECURITY.md` lists 0.2.x as supported (0.2.0 to 0.2.3 are on npm) instead of 0.1.x, and no longer calls parsed-evidence `done` v2 unreleased: it shipped in 0.1.2 (`git show v0.1.2:src/cli/commands/done.ts` calls `parseEvidence`). `docs/measurements.md` had the same word. `SECURITY.md`, `docs/privacy.md`, `docs/recipes/github-action.md`, `docs/measurements.md` and the dashboard's Privacy tab said that for recognised output only counts, the exit code and failing test names reach Jev, and that a note in the log never does; the matched summary line and exit-code lines are sent as text too (since 0.1.2), so a note written on one of them reaches Jev. They now say so.
- `docs/configuration.md` lists all 11 questions of the `generic` pack (the four `stop.*` questions were missing) and the threshold groups and keys the code reads, including `stop.gate`, one group for the four `stop.*` questions, and which keys a project file may only raise or only lower.
- `scripts/real-ci/fetch2.mjs`: `stats.json` sums the `gh` calls of every pass. Before, each pass overwrote `calls`, so the `--aggregate` pass, which calls nothing, left 0, and the `--langs` and `--topup` passes exited without saving their counts at all. Each pass now leaves a record in `passes/` with every language it walked, so a later pass that excludes nothing replaces an older pass's count with 0 instead of keeping it.
- `receipts --stops` and the dashboard show a stop's `error` (the error code when the stop got no answer: a Jev error, a redaction stop, a missing or bad key, a pack that does not load, or internal) and `configured: "active"`, which the stop records carry since this release but no view showed. The Flow tab says "Not asked: jev error, error rate_limited" and "shadow mode (set to active, not built)"; the labelling card names the configured mode.
- `ROADMAP.md`, `docs/measurements-done-bar-split.md` and the real-log suite note said the real-log sample had no Jev answers and listed recording them as the next step. The answers were recorded on 2026-10-05 (199 cases). `scripts/done-bar/split.mjs` now counts the recorded verdicts per part and class into `classes.json`, and the documents give those counts: at the registered code the hold-out has wrong `met` 0 of 33, `missing` recall 19 of 33 and R `met` recall 20 of 28 (not evaluable); later code 28 of 38 and 29 of 38 (second looks).

## [0.2.3] - 2026-10-06

Fixes and additions that came out of testing on real code. `decide` asks a balanced set of option orders when its two orders tie; `extract` no longer lists already translated Vue mustaches (the cause of every wrong `yes` on the first real-code test of the `i18n` pack) and reads HTML templates inside `<script>`; new `done` parsers for `mix test`, `ctest` and `rubocop`; the dashboard shows stop marks and grouped numbers. The `i18n` pack failed its bar on the first real-code sample and held it on a second one (0 wrong answers on 116 candidates, only 9 of them technical, a definite answer on 18).

### Added

- `extract` reads HTML templates kept inside `<script>` elements of type `text/html`, `text/x-red`, `text/template`, `text/x-template` or `text/ng-template`, such as Node-RED's editor and help templates; other scripts are still skipped. On the Node-RED repository of the second real-code sample, found removed `data-i18n` keys went from 0 to 39 of 41 (fitted: the rule was written for that repository); the other 12 stripped copies of both samples give exactly the same candidates as before (`docs/decisions/extract-script-templates.md`).
- `ui`: each labelling card lists the marks stored with the stop, read in code and never sent to Jev (checks with cut-off output, subagent calls, subagents or background tasks that finished, and a pass only in the previous turn); a stop without marks shows no line. Overview and privacy counts are grouped by thousands (`12,963`). Checked in headless Chrome through agent-browser on synthetic stops (marks, plain card, overview, a 375 px width), with no console or page errors.
- `done` parsers for `mix test` (ExUnit summary, excluded tests count as skipped and cap `met`), `ctest` (summary, `Total Test time`, failed and not-run blocks) and `rubocop` (summary, offenses, corrected offenses, warnings and notices), written from the dev half of the second real-log sample (`docs/decisions/real-logs-2-split.md`, `docs/decisions/real-logs-2-parsers.md`). `cmake --build`, `make`, wrapper builds, `phpstan` and `xcodebuild` were skipped (too few dev examples, or no success marker in the tool's output). Five synthetic cases of `done-v2-h3` and `done-v2-h4` were re-recorded because their logs are now parsed; no suite allowance moved.
- An eval `suite.json` may name a `pack`; `eval record` and `eval score` use it for that suite, an explicit `--pack` still wins, and `eval score --suite all` scores each suite with its own pack. Before, a suite on a pack other than the project's (such as `judge-i18n` on `i18n`) failed `--suite all` with `bad_pack` as soon as it had a recording. `eval record` refuses to record suites on different packs in one run.

### Changed

- The GitHub Action recipe has a "How it is tested" section, and the roadmap no longer makes a Marketplace listing wait for a hosted-runner run with a key: the maintainer decided on 2026-10-06 not to store a TypeSafe key in this repository, so that path is covered by `test/action.test.ts` with a stub CLI only.
- The `verify` skill recipe no longer says that `npx claude-referee` fails with a 404 until the npm publish, and no longer points to the README alias that 0.2.1 removed; the package is on npm (0.2.0 to 0.2.2). The roadmap status table follows the releases and npm, and cites the rewritten commits instead of seven hashes that are no longer in `main`.

- `decide`: when the written and the reversed order tie (they pick different leaders, or the top two are less than `margin` apart) and there are 3 to 6 options, it also asks the other 2n - 2 orders of a balanced set (the n rotations of the written order and their reverses) and takes lean and verdict from the mean of all 2n; the output says how many `orders` were asked. Registered before any code ([record](docs/decisions/decide-balanced-near-ties.md)): replayed on the order study's recorded answers it raised near-tie agreement with the all-orders leader from 21 of 32 to 30 of 32, lost nothing elsewhere and fired on 21% of decisions with 4 or more options (3.5 requests per decision on average instead of 2); the shipped command matched the study's harness within 0.008 on 8 live decisions. Chosen with Jev below the acceptance bar (p 0.82, both orders) as the option easiest to undo ([next-work-2026-10-06.md](docs/decisions/next-work-2026-10-06.md)).
- `eval record` records those extra orders for tied decide cases and tops up older recordings with only the missing orders; `eval score` asks for them when they are missing; `--max-requests` counts the most they could add; the `context` and `reversed` ablations keep two orders. `decide-best` was topped up (14 cases, 84 requests): agreement with the author labels stayed 16 of 39, verdicts went from 25 `weak` and 14 `tie` to 28 and 11.

### Fixed

- `extract`: a Vue text node that is only a mustache whose expression holds braces, such as `{{ $t('key', { min: 0 }) }}` on one line or several, is no longer listed as a candidate; text outside mustaches still is. Before, the mustache check stopped at the first `}` inside the expression, so already translated calls with interpolation values reached `judge`. - Stop done-gate marks in `stops.jsonl`, code-side facts only and not sent to Jev (no measurement shows that sending them helps): `truncated_checks` (checks whose output was cut), `subagent_calls` (Agent or Task launches in the turn), `subagent_reports` (subagent or background-task finish notifications in the turn), `stale_pass` (the turn edited, has no passing check after its last edit, and the previous turn had a passing check; a final message that says "tests pass" may be repeating that). Each appears only when it applies, on skipped and asked stops alike, and none can turn a stop into a skip.
- `done` parses `cargo nextest`, Perl `prove`, `dart test`, `flutter test`, Julia `Pkg.test` summaries, `behave`, `kaocha`, `tox` (4 and 3), `biome`, `next build` and `nix build` output in code, written from real runs and the tools' own source ([sources and limits](docs/decisions/runner-parsers-met-recall.md)). `cargo nextest` logs were read by the `cargo build` parser with no tests counted; they no longer are. Failures, errors, skips, pending items, a missing summary or a run that tested nothing give facts that cannot be `met`. On the fifth hold-out text the changed cases moved to dev (9 of 11 expected `met` now `met`, 0 wrong `met`; dev numbers, not a pass).

The plugin does not install it; a test checks its frontmatter. The recipe appends an `exit code:` line, says what to do without a verdict (for example the pre-publish npx 404), and the page carries a not-on-npm note and a privacy note (test output is sent to the TypeSafe API).
- `receipts --stops`: a weak label hint for an unlabelled `would_block` stop, read from the user's next prompt in the session transcript. Only `right` is ever suggested, with reason `reported_broken` (the prompt says it does not work, fails, errors, English or Turkish; negated, hypothetical, question and instruction clauses such as "no crash", "add a failing test" or "do not run the tests" are ignored, so a missed report is preferred over a wrong hint) or `repeated_request` (it largely repeats the prompt of the turn that stopped). Approval, thanks and silence suggest nothing (decided with Jev, p 0.95, both orders). The hint is computed on read, stored nowhere, never printed with the message text, never counted in stats and never overrides a human label.
- `receipts --stops` returns `threshold_suggestion`: available only with at least 10 human labels of each class on `would_block` stops. It uses exact Clopper-Pearson 95% intervals (no dependency) and suggests the smallest `claims_done` at or above the current threshold whose kept labelled stops have a precision lower bound of 0.8 or more, or null; it never suggests lowering it and writes nothing.
- `hooks.stopGate: "soft"`: like `shadow`, and when Jev would block the Stop hook also prints one `systemMessage` warning (shown to the user, no block, no context for Claude). Stops are recorded with `mode: "soft"`.
- Receipt integrity: each receipt carries `prev`, the sha256 of the previous line of its project's chain, and `receipts verify [--project-only]` reports breaks (`mismatch`, `fork` from two runs appending at once, `unreadable`); receipts written before this are counted as `unchained`. `receipts overrule <id>` records a human veto in `overruled.jsonl` and deletes the cached answers that receipt used, so the next run asks Jev again. Receipts now list the `cache_keys` they used. The chain detects edits and deletions in the middle of the history; it does not stop someone who rewrites it from the start or truncates its end.
- `eval` now handles `decide` suites. `eval record` asks both option orders per case; `eval score` reports leader agreement with the labelled best option, the clear/weak/tie mix, order disagreements and agreement per verdict as raw counts, with no precision, recall or pass/fail threshold. Metric choice and first numbers: [docs/decisions/decide-eval-metric.md](docs/decisions/decide-eval-metric.md).
- `eval record` and `eval score` take `--ablation context|reversed` for decide suites: `context` leaves the context text out of the request, `reversed` asks the written order only (rescored from the same recording, no request).
- New suite `jev-evals/decide-best`: the 39 close-call decisions with one author-written best option each, recorded against `jev-1.13.0`.
- More credential formats stop a request before it is sent: Stripe live keys (`sk_live_`, `rk_live_`), npm, PyPI, Hugging Face, SendGrid, Google API and GitLab tokens, Telegram bot tokens, Azure storage `AccountKey=` values, Docker `auths` entries, Slack webhook URLs and `xapp-`/`xoxe` tokens, and PGP and PuTTY private key blocks. Test and publishable Stripe keys are kept. Each format has stop and keep fixtures; which formats were added, why, and which were left out (Twilio, Mailgun, Discord) is in `docs/decisions/redaction-patterns.md`.

### Documentation

- `docs/decisions/decide-policy.md`: `decide` keeps two separate requests (written and reversed order) for 2 to 6 options. One request with two questions and balanced rotations were not adopted: no measured benefit beyond noise, and nothing measured for other than 4 options. Jev decide: keep two requests 0.99, both orders agreeing.

### Fixed

The token pattern requires the `AA` secret prefix, so numeric strings like `20260101:...` no longer stop; Hugging Face tokens need a digit, so long identifiers such as `hf_getUserSessionToken...` no longer stop.

## [0.1.0] - 2026-09-30
