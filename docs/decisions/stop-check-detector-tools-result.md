# Result: the Stop gate counts more real toolchain checks

Result of [stop-check-detector-tools.md](stop-check-detector-tools.md), 2026-10-07. Both rules were built as registered and replayed against base `c1cd69b`; no new Jev request was sent. A review then narrowed rule 1 in three places, capped the joined check text and fixed one tokenizer case; those changes are described below, and every replay here was run again on the final code. This is a change fitted to tools seen in real use, not a clean test.

## What was built

All in `src/engine/stopgate/transcript.ts`; tests in `test/stopgate-check-tools.test.ts` (8 tests on invented commands shaped like the real ones; 7 of them fail on base, the eighth guards look-alikes; 5 fail on the code as it was before the review).

1. **Rule 1, `checkKind`.** The pass and fail reading (`rawStatus`) is unchanged; only `vue-tsc` is silent.
   - `node --test`: the exact token `--test` with only flags before it. `node script.mjs --test` passes the flag to Claude's own script and stays out, as [stop-check-detection.md](stop-check-detection.md) decided. A run is also left out when an argument after `--test` starts with `/tmp/`, `/private/tmp/`, `/var/folders/`, `/private/var/folders/` or `$TMPDIR`: a test file in a temp dir is Claude's own probe, not a project test, and counting it would count Claude's own code runs, which that decision did not do. A redirect target is not a test file, so `node --test test/ > /tmp/out.log 2>&1` still counts.
   - `php -l` (first argument) and `php artisan test`.
   - `phpstan` under any path (`vendor/bin/phpstan`) when it has no positional argument or `analyse` comes first. Redirects (`2>&1`, `> file`) are not positional arguments. Not counted: any call with `--version`, `-V`, `--help` or `-h`; `clear-result-cache` and other subcommands; the spelling `analyze`, which the registration does not name.
   - `composer <script>`: the first argument after flags matches the script pattern as it was before this change (`test`, `lint`, `typecheck`, `check`, `build`, optionally `:suffix`), or is exactly `analyse`. `composer ci`, `composer verify` and `composer run-script <name>` are not counted.
   - `vue-tsc` is silent like `tsc`, except that a call with `--version`, `-v`, `--help` or `-h` is not counted: as a silent check with no failure text, it would read `passed`. `prettier` counts only with `--check` and `pint` only with `--test`. `oxlint` is a direct tool and also counts through `npx`, except with `--version`, `-V`, `--help` or `-h`. None of these except `vue-tsc` is silent.
   - Package scripts `ci`, `ci:*`, `verify` and `verify:*` count through `npm|pnpm|yarn|bun run` (or `run-script`), and bare (`pnpm verify`, `yarn ci:lint`). A bare `ci` is not counted, because `npm ci`, `pnpm ci` and `bun ci` install packages and do not run a script.
   - Flags between `run` and the script name are skipped (`npm run -s test`, `npm run --silent lint`).
2. **Rule 2, the stored check.** The stored check holds the matched check segments as written (quotes kept), each clipped to 200 characters, in order. Each one after the first is joined by the separator that came before it (`&&`, `||`, `|` or `&`; `;` and a newline become `; `). Every other segment is dropped: the leading `cd`, a `| tail -20`, an `echo`. Heredoc bodies are dropped before the command is split, and so is a leading `{` group opener. The joined text is capped at 1,000 characters. The registration sets only the per-segment cap; without a total cap, one command with thousands of checks would send all of them to Jev. The longest joined check in all local transcripts is 371 characters, so the cap cuts none.
   - The tokenizer keeps `&` inside a redirection (`2>&1`, `>&2`) as part of the word, and `&>` starts a new word even with no space before it (`npm test&>log` reads as `npm test` and `&>log`, as on base). Without the first change the stored segment would read `npm test 2>`. No detection changed: every Bash call counted on base is still counted (scans below).

Hook bundle: 157,509 to 159,813 bytes.

## Real-use replay

The replay covered the 128 stop records on this machine (53 in this repository, 75 in other projects), each transcript cut at its stop time. Only aggregate numbers are given.

- **Asked stops.** Of 14 recorded asked stops (9 here, 5 in other projects), 1 moves to `check_passed_after_edit`: an other-project stop where `composer test` passed after the last edit. Its recorded answer did not block it (shadow mode; claims_done 0.09). The other 13 are still asked. Of the 54 background stops that would have asked (7 here, 47 elsewhere), none moves. No skip reason moves the other way, and no stop's check count goes down.
- **State sent to Jev, for the 13 still-asked stops.** The state is unchanged for 5. It has more checks for 8 (7 here, with `node --test` or `npm run ci:local`, and 1 elsewhere). The stops that send `checks: []` fall from 10 to 5.
- **Stored checks.** The registration counted distinct checks per session: on base, 15 of 37 stored texts had no check segment left. On the new code, 0 of 85 have none.
- **Newly counted checks in stop turns.** Taking the last stop of each of 60 turns, 69 checks are newly counted. Here: 33 `node --test` (9 passed, 7 failed, 17 unknown) and 32 `npm run ci:local` (2 passed, 30 unknown). In other projects: 2 `php -l` (unknown), 1 `phpstan` (failed) and 1 `composer test` (passed). Before the review there was one more `node --test` pass; its test file was in a temp dir. Most new checks reach Jev as `unknown` or `failed` facts; few end up skipping a stop.
- **What the review changes did on real calls.** All 12,334 main-thread Bash calls in the 2,496 local transcripts were run, with their real results, through the code before and after the review. 1 call is no longer counted (a `node --test` on a temp-dir file that read `passed`), 2 calls keep their other check but drop a temp-dir `node --test` segment from the stored text, and 1 `oxlint --version` is no longer counted (it read `unknown`). The `phpstan` redirect, `&>` and cap changes alter no real call. Treating every temp path after `--test` as a test file, the review's first suggestion, would also have dropped 10 project test runs whose output went to a temp file (8 passed, 2 failed); skipping redirect targets keeps them counted.
- **Coverage over all transcripts on this machine.** This uses the earlier scan's fixed check-like pattern; the transcripts have grown since the registration's count. In other projects, 2,294 of 3,423 segments were counted on base and 3,013 are counted now. In this repository, 1,118 of 1,878 were counted and 1,808 are counted now. No segment counted on base is uncounted now. Of the registered tools, 723 segments elsewhere were uncounted on base and 4 still are: 3 `phpstan` with something other than `analyse` first, and 1 `vue-tsc --version`, left out on purpose. Here, 686 were uncounted and 23 still are; most come from this study's own probe scripts (version and help flags, temp-dir test files), plus `node` with a script or an `--import` value before `--test`. The largest uncounted groups left are outside the registration: `pint` without `--test` (222), `prettier` without `--check` (105), `vp fmt` (49), `vp lint` (19) and `npm run format` (18).

## Limits

- No recorded suite runs a newly counted tool. So the suites cannot show the risk the bar guards against: a wrong "done" that skips because one of these checks passed after the last edit. The only evidence is real use: one stop moved, it carries no right-or-wrong label, and Jev did not block it.
- **`ci` and `verify` scripts can read `passed` from an early stage.** The pass reading is unchanged, and for a script that runs several stages it can take one stage's test summary for the whole run when the exit status does not reach the tool result. Over all local transcripts, 7 newly counted `npm run ci:local` runs read `passed`, all in this repository and all filtered through a pipe or redirected to a file. 2 of the 7 were failed runs. One was redirected to a file, printed `exit 1` (not the `exit code: N` line the parser reads), and then showed a node:test summary with 0 failures from the file's tail. The other was piped through `grep` while a later step reported `ok: false`. In invented runs, one that fails at the bundle step with no npm error lines and is cut by `| tail -30` reads `passed`, and a run cut by `| head -30` before its later stages reads `passed` whatever those stages did. No recorded or real-use stop moved because of this. A fix would either keep `passed` for these scripts only when their exit status reaches the tool result, or drop `ci` and `verify` from rule 1. Both go beyond the registration's "same pass and fail reading", so neither was done here. The same weakness exists on base for `npm run check` and `npm run build`.
- **`node --test` and Claude's own test files.** Only a temp-dir path after `--test` marks a run as Claude's own. Still counted: a project test file the same command writes or appends to with a heredoc (in this repository 20 such calls wrote or appended tests to project test files; none read `passed`), a `cd` into a temp dir followed by a relative path (none seen in local transcripts), and a temp file named through another variable. A temp path given as a separate flag value (`--test-reporter-destination /tmp/r.txt`) leaves the run uncounted. A name filter that matches no test reads `passed` (0 tests, 0 failures), the same reading `npm test` gets on base.
- **Narrow checks skip a stop when an exit code line is visible.** `php -l`, `prettier --check`, `pint --test` and `phpstan` have no parser, so they pass only when an exit code line is visible; otherwise they reach Jev as `unknown`. The user's usual `; echo "exit code: $?"` makes them pass, and then they skip a stop like any passed check: `php -l one.php 2>&1; echo "exit code: $?"` checks the syntax of one file, and `npx prettier --check README.md docs/` checks only the formatting of docs, yet either skips the stop after an edit. `oxlint` with warnings and no errors reads `passed` (parsed, 0 errors), the same reading eslint warnings get. Over all local transcripts, newly counted calls of these kinds have not passed yet: `php -l` 132 (0 passed, 1 failed), `prettier --check` 7 and `oxlint` 2 (all `unknown`). The registration names these tools, and the bar does not cover them.
- Strict readings that are not counted: `phpstan analyze`, `phpstan -c file` (the config path is taken as the first positional), `prettier -c`, `composer run-script <name>`, `composer analyse:*`, `node --import X --test`, `php vendor/bin/phpstan`, and a check after `do` in a shell loop. `phpstan`, `vue-tsc` and `oxlint` with a version or help flag are not counted. `tsc --version` and `eslint --version` still count as on base, outside this registration, and their silent reading makes them pass.
- The `stop-req` fresh set is not replayed, as noted above. The real-use stops were all in shadow mode, with one Jev model version and no labels.
