# Recipe: find strings that should be translated

The `i18n` pack answers one question per candidate string: is this shown to end users in the interface, so that it should be translated? Code finds the candidates; Jev only judges them, one request per item.

```sh
# 1. Find candidates. Offline, free, no key.
npx claude-referee extract src --out .claude/i18n-items.jsonl

# 2. See exactly what would be sent, and the cost, before spending anything.
npx claude-referee judge --pack i18n --question string.translatable --items .claude/i18n-items.jsonl --dry-run

# 3. Judge. Exit code 3 when something is flagged.
npx claude-referee judge --pack i18n --question string.translatable --items .claude/i18n-items.jsonl --fail-on flagged
```

`flagged` lists item ids as `path:line`. `review` ids are the ones between the bands (0.1 to 0.9): look at those yourself. To adopt the check on an existing codebase, record today's findings with `--baseline .claude/referee-baseline.json --baseline-write` and fail only on new ones, as in [judge --baseline](../judge-baseline.md). The baseline keys on the string text, not the file or line.

## What `extract` finds

A hand-written scanner, not a parser. It reads these extensions: `.jsx .tsx .js .mjs .cjs .ts .mts .cts .vue .html .htm`.

| Kind | Where |
|---|---|
| `jsx-text` | Text between JSX tags; a `{expr}` inside it is kept as `{expr}`, so `Welcome back, {user.name}!` is one candidate |
| `jsx-attr` | `placeholder`, `title`, `alt`, `aria-label`, `aria-description`, `aria-placeholder`, `label`, as a quoted value or a string in `{...}` (also the arms of `a ? "x" : "y"`) |
| `jsx-expr-string` | A string child such as `{loading ? "Loading..." : "Done"}` or `{error && "Failed"}` |
| `vue-text`, `vue-attr` | The `<template>` block; bound attributes (`:title`) and `v-`/`@` directives are ignored; `{{ 'literal' }}` counts, other mustaches do not. A Vue `<script>` is scanned like a `.ts` file |
| `html-text`, `html-attr` | Plain HTML text and the same attributes, `meta` description and social titles, and the `value` of submit and button inputs |
| `ui-call` | A string argument of `alert`, `confirm`, `prompt`, `toast`, `toast.*`, `message.*`, `notification.*`, `snackbar.*`, `Swal.*`, `Modal.*`, `notify`, `showToast` and similar |
| `ui-prop` | A string value under `label`, `title`, `text`, `message`, `description`, `placeholder`, `tooltip`, `helperText`, `errorMessage`, `caption`, `heading`, `hint` and similar object keys |
| `ui-assign` | `document.title = "..."`, `el.textContent = "..."`, `.innerText`, `.placeholder` |

## What it leaves out

- Strings already wrapped by a translation call or marker: `t()`, `i18n.t`, `$t`, `formatMessage`, `gettext`, `ngettext`, `_()`, `msg`, `$localize` (calls and tagged templates), `<Trans>`, `<FormattedMessage>`, and elements marked `data-i18n`, `i18n`, `v-t` or `translate="no"`; Angular `i18n-title` style attribute markers.
- Anything inside a log call (`console.*`, `logger.*`, `log.*`) or a test call (`describe`, `it`, `test`, `expect`, `getByText`, `toThrow`...).
- Technical strings by shape: no letters, URLs, paths and file names, hex colours, regex-looking strings, SQL, shell commands, identifiers (camelCase, snake_case, kebab-case, dotted keys), constants, class lists, `key:value` tokens, emails.
- Imports, class names, ids, `href`/`src` and every other attribute: only strings in the positions above are ever candidates.
- Text inside `<code>`, `<pre>`, `<kbd>`, `<script>`, `<style>`, `<textarea>`; `node_modules`, `dist`, `build`, `coverage`, `vendor`, hidden directories; `*.test.*`, `*.spec.*`, `*.stories.*` unless `--include-tests`.

Known limits: no AST, so a string the scanner cannot place (a label built in a helper, a string in a variable, a `.tsx` generic arrow such as `<T,>(x) => x` that makes the surrounding JSX unreadable) is not found. Svelte, Astro, Angular inline templates, PHP and Blade are not read. A string in a UI position is a candidate even when it is not really UI text; that is what the judge step is for. Identical candidates (same kind, text and surrounding element or call) are listed once; `--keep-duplicates` lists all.

Large sets: the judge takes at most 500 items per call. Use `extract --offset 0 --limit 500`, then `--offset 500`, and so on.

## Accuracy

Two measurements, both pre-registered ([evaluation](../decisions/i18n-pack-eval.md), [numbers](../measurements.md#extract-and-the-i18n-pack-on-real-repositories)):

- **On real code** (four public React and Vue repositories, 2026-10-06): in copies whose translation calls were turned back into plain strings, `extract` found 1,725 of 2,463 of those strings (0.70). It finds nearly all JSX and Vue template text (0.97 and 0.96) and most JSX attributes (0.83), but under half of the strings in other JS and TS expressions (object values, call arguments, variables: 0.44), and none left inside a Vue binding. The judge then gave a definite answer on only 32 of 157 real candidates and never answered `no`: expect most candidates in `review`. It made no wrong `no` (0 of 120 UI strings) but 5 wrong `yes` among 37 items labelled not to translate, all of them already translated calls inside a Vue mustache that `extract` listed by mistake (fixed after the measurement, so the fix itself is not measured yet). The registered bar (no wrong answer either way) failed.
- **On a second real sample** (nine more repositories, the fixed `extract`): `extract` found 2,124 of 2,790 (0.76); it reads no text inside `<script>`, so HTML kept in script templates (such as Node-RED's) is missed. The judge made no wrong answer on 116 hold-out candidates (only 9 of them technical) and decided 18 of them. A reworded question was tried and not adopted, because it reached `no` no more often than the shipped one; it also decided fewer.
- **On invented strings** (95 hold-out items): no wrong `yes`, no wrong `no`, a definite answer on 53.

So on real code `review` is the normal answer, and 5 of the 32 `flagged` items were wrong: read the flagged list before acting on it.

The design choice (a separate `extract` command feeding `judge --items`, not a `--files` flag on `judge`) and its Jev receipts are in [decisions/i18n-command-surface.md](../decisions/i18n-command-surface.md).
